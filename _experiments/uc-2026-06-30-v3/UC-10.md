# UC-10 — O Arquiteto — Blueprint Estratégico do Gobus MCP v3
> **Data:** 2026-06-30 | **Status:** ✅ Completo

## Briefing
Com tudo o que aprendemos nos 9 UCs anteriores, o que deve mudar na plataforma? Os UCs não foram bem-sucedidos por gerar análises bonitas — foram bem-sucedidos por gerarem o **diagnóstico do que falta** para que essas análises sejam reproduzíveis por qualquer agente sem que ele tenha de reinventar workarounds de GraphQL a cada chamada. Este UC consolida esse diagnóstico em um RFC de evolução acionável.

## Resultado

### (A) Sumário executivo — impacto esperado de cada categoria de melhoria

A plataforma Gobus MCP hoje entrega **dados brutos competentes** (6.399 artigos/30d, 140 agências ativas, 25 temas, ~213 artigos/dia) mas **falha em três níveis** que os 9 UCs expuseram de forma sistemática:

1. **Transporte (MCP):** as tools `mcp__gobus__*` falharam em 100% das chamadas de subagente (`-32602`) porque a sessão SSE não persiste entre invocações. Impacto da correção: **destrava todo o resto** — sem isso, nenhum tool novo é utilizável por agentes em paralelo.
2. **Confiança dos dados:** quatro pipelines estão mortos ou ruidosos (`trendingScore`=null, `viewCount`≈null, sentimento sempre 0% positivo, Flesch com valores impossíveis abaixo do piso teórico). Impacto: análises de tendência/impacto/sentimento são atualmente **não-confiáveis** — corrigir devolve credibilidade a 4 das 8 famílias de tool propostas.
3. **Cobertura analítica:** o Panorama DGB cobre o *descritivo* (volume, sentimento, mapas) mas nenhum dos **9 padrões inferenciais** que os UCs provaram serem possíveis e valiosos (proto-crise, ciclo de vida de política, coerência inter-agência, difusão, equidade NER-based, forecast com correção de borda, score de artigo, ranking de legibilidade acionável, lead/lag económico). Impacto: cada gap fechado vira um tool MCP + um App `ui://` que transforma a plataforma de "dashboard" em "copiloto analítico".

### (C) Roadmap em 3 fases

- **Quick Wins (≤ 2 sem):** fix transporte MCP; `gobus_get_readability_recommendations` (usa Flesch já existente, só precisa ordenar+recomendar); correção do bug de sentimento e do piso de Flesch (clamp + reprocessamento).
- **Core Features (1–2 meses):** fix `trendingScore`; `gobus_detect_anomalies`; `gobus_forecast_trends`; `gobus_score_article`; expor `Article.entities[]` e `Article.wordCount`/`publicationHour`. Primeiros 2–3 MCP Apps (`ui://readability-dashboard`, `ui://anomaly-radar`, `ui://forecast-radar`).
- **Advanced (3+ meses):** `gobus_get_message_coherence`; `gobus_get_diffusion_map` (+ `firstSeenByAgency`); `gobus_get_policy_lifecycle`; `gobus_get_entity_lead_lag` (após acumular >1 ano de janela NER); Apps `ui://coherence-matrix`, `ui://diffusion-timeline`, `ui://equity-map`, `ui://policy-timeline`, `ui://correlation-chart`.

### (D) Requisitos técnicos por item
- **Transporte:** migrar FastMCP para o endpoint HTTP stateless `/mcp` (spec MCP 2025) com fallback SSE; eliminar dependência de sessão persistente entre chamadas.
- **Pipelines:** re-ativar job que popula `trendingScore`; clamp de Flesch ao piso teórico + auditoria do tokenizador PT-BR; revisar léxico de sentimento (provável bug de normalização que zera o eixo positivo).
- **Schema:** `Article.entities: [Entity!]!` (NER canónico já existe na tabela `news_features`); `Article.wordCount: Int`; `Article.publicationHour: Int`; `Entity.firstMentionDate`; campo de difusão `firstSeenByAgency`.
- **Tools:** cada tool é uma view sobre queries GraphQL existentes (`agencyAnalytics`, `trendingThemes`, `articlesTimeline`) + lógica de agregação no servidor MCP.

### (E) KPIs pós-implementação
- Taxa de sucesso de tool-call em subagente: **0% → ≥99%**.
- `trendingScore` não-nulo: **0% → ≥95%** dos artigos.
- Cobertura dos 9 padrões inferenciais por tool MCP: **0/9 → 9/9**.
- Tools que dependem de workaround GraphQL manual: **8 → 0**.
- Tempo médio de um agente para responder uma pergunta analítica (ex.: "há proto-crise?"): de *múltiplas queries manuais* para *1 tool-call*.

## Gaps e Surpresas

**Bugs sistémicos confirmados (pré-requisito de tudo):**
- **Transporte MCP** — sessão SSE não persiste entre chamadas de subagente → `-32602` em 100% dos casos. O endpoint stateless `/mcp` resolveria, mas Claude Code ainda negocia spec 2024-11-05. Maior bloqueador da plataforma.
- **`trendingScore` = 100% null** em junho 2026 — pipeline morto, não degradado. Toda análise de tendência hoje depende de proxies (Flesch+wordCount), o que é uma fragilidade arquitetural.
- **Sentimento sempre 0% positivo** — bug persistente de léxico/normalização.
- **Flesch com valores abaixo do piso teórico** (ex.: -46.6 no aviso do INSS) — pipeline ruidoso; falta clamp e auditoria do tokenizador.
- **`viewCount` ≈ null** (máx 7 views) — inutilizável; qualquer "Mais vistas" ou score de impacto precisa de fonte alternativa (Umami) ou proxy.

**Gaps de schema mais críticos (descobertos pelos UCs):**
- `Article.entities[]` ausente (UC-03/04/05) → impossível fazer coerência, difusão ou equidade NER-based via API; UCs tiveram de ir ao Postgres direto.
- Sem dimensão temporal por agência (`firstSeenByAgency`) (UC-04) → `entityNetwork` não reconstrói ordem de difusão.
- Republicadores (`agencia_brasil`, `tvbrasil`, `ebc`) tratados como emissores originais (UC-03/04) → inflam diversidade e distorcem difusão.
- Políticas públicas não canonicalizadas como entidades nomeáveis (UC-02/09: `dgb_taxa-selic`, `Pé-de-Meia` = 0 artigos NER) → ciclo de vida e lead/lag ficam cegos por nome.
- Janela NER de apenas 18 semanas (desde 2026-03-01) (UC-09) → inferência de correlação/lead-lag estatisticamente frágil; é questão de tempo, não de código.
